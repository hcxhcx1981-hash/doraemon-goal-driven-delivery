# CODE_DEV 任务规则（references 一层引用自 SKILL.md 的 CORE，不嵌套第二层引用）

适用：交付物为代码、功能、修复、配置变更的 CODE_DEV 类任务（V1.2 BUILD 已映射为 CODE_DEV）。

## 执行流程
基线核验（一次）→ 技术方案 → 实现 → 测试 → 故障定位 → 修复 → 真实验收 → 收口

## 规则
1. 一次基线检查：最小范围核验目标项目/文件、已完成能力、Git 状态、工具可用性；优先复用已验证方案；禁止反复全仓审计。
2. 每轮修复记录四要素：根因假设、支持证据（错误日志/测试/定位）、最小修改、验收方式。
3. 不擅自重构无关模块；修改只覆盖必要部分。
4. 不把局部测试通过说成产品完整交付；验收走端到端业务链或真实可运行证据。
5. 按项目授权处理 Git 提交与推送；未授权推送写 NOT_PUSHED。
6. 常见构建失败/参数冲突/工具问题：先错误证据定位，再最小修复；同一根因 ≤2 轮、单任务 ≤4 轮，无新证据（新错误/新定位/验收变化三选一）即停，禁改名/拆分/重启规避。

## 收口补充
DELIVERED 写清产物路径/运行入口；ACCEPTANCE 列真实验收项与证据；REPOSITORY 写分支/commit/推送状态。
