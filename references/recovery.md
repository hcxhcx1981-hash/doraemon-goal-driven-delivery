# 熔断、异步防护、预算与跨会话恢复（继承 V1.2 熔断 A–E，V2 增补）

## 1. 修复熔断（继承 V1.2 规则 A/C/E）
- 同一根因最多 **2 轮有证据修复**。
- 单个独立任务最多 **4 轮有效修复**；项目有明确更严限制时以更严为准。
- 无进展/无新证据时立即停止相关修复。
- 禁止通过改名、拆分任务、重启会话规避修复计数。

### "有效新证据"判定（V2 成文，消除主观）
一轮是否计为"新一轮"，必须至少出现以下之一：
- 新的错误信息或新的复现结果
- 找到此前未知的根因或定位
- 产生可验证的验收变化（某项从 FAIL 转向 PASS 或更小范围 FAIL）

仅"换一种说法""重新跑一遍相同操作""重新尝试"不算新证据，应计为同一轮并触发停止。

### 每轮必须记录
根因假设 / 支持证据（错误日志、测试结果、代码定位）/ 最小修改（只改必要部分）/ 验收方式（如何确认该轮有效）。

## 2. 异步工具与无限轮询防护（V2 新增）
- 启动异步任务后，优先等待其完成通知/事件，而不是主动轮询。
- 仅当确实需要查询状态时才轮询。
- 连续两次查询状态**无变化**即停止重复轮询。
- 不得因等待超时反复创建相同任务。
- 不得用重启、重新派发、创建新线程来规避预算或掩盖卡顿。
- 无法判断任务是否仍在执行时，保留任务 ID，报告当前状态，不盲目重启。

## 3. 预算机制（任务规模 S/M/L，由派工设定，更严优先）
按任务规模设定时间、工具调用次数、模型预算：
- **S**：单文件/单问题小型修改
- **M**：单模块功能/单份完整报告
- **L**：跨模块/跨会话交付

具体时间/调用/模型数值由派工任务结合实际工作量设定，**不使用未经实测的统一固定数字**。Agent 必须区分三类约束并分别标注：
- 宿主真实强制限制（可程序执行的硬限制）
- 任务派工预算（派工方给定的软/硬边界）
- Agent 自我记录的软预算（自约束）

**不得把软约束宣称为程序级强制熔断**（软规则无法阻断宿主；硬限制才由宿主机制强制）。

达到预算后：优先保留已完成的、已通过验收的成果，并以 **PARTIAL 或 BLOCKED** 收口，不得为冲 PASS 继续烧预算。

## 4. 额度保护（继承 V1.2 规则 D）
- 不自动购买 Token/额度/付费资源
- 不无限调用外部模型
- 不为证明稳定而重复付费测试
- 无法读取剩余额度时标记 `QUOTA=UNKNOWN`
- 真实 API 调用次数受任务预算约束
- 不得以"自主执行"为由绕过节流/预算

## 5. 熔断后动作（继承 V1.2 规则 E，V2 通用化交接对象）
触发熔断后依次：
1. 停止相关修改与重试
2. 保留已完成且通过验收的成果
3. 保存错误信息与必要证据
4. 记录已尝试的修复方案
5. 标记 `BLOCKED` 或 `PARTIAL`
6. 提供下一步技术建议
7. **仅在需要外部决策时，提交上述证据与建议给授权责任方处理**（任务发起方/授权责任方/指定接收方由任务约定；本协议不预设任何具体模型、Agent、平台或中心控制器）

**禁止把普通技术方案选择甩给用户**；仅实质风险、不可逆操作、授权越界才需授权责任方介入。禁止未经授权转包。

## 6. 跨会话状态恢复（仅 L 级任务启用）
- 小任务（S/M）**不创建台账**，避免治理成本超过任务成本。
- L 级任务在任务工作区根目录写 `task-ledger.json`（结构见 `schemas/task-ledger.schema.json`）。

### 恢复流程
1. 新会话先检查相关未完成任务
2. 读取台账并核验已完成成果是否仍存在（成果哈希）
3. **继承原任务的修复轮次计数与预算**（改名/重启不重置）
4. 不重复已验证完成的工作
5. 只有确认原任务已结束，才清理临时任务状态
6. 不将台账写入公开 GitHub；不记录密钥/Token/Cookie/真实敏感数据

### 恢复点字段
台账须含 `next_action`（下一步动作）作为恢复入口；重开会话从恢复点继续，继承而非清零计数。

## 7. V1.2 治理规则全文恢复（审计项 1：CORE 只留指针，全文在此，不删）

### 7.1 项目规则优先级（V1.2「与其他规则的关系」）
平台安全规则、用户明确授权、项目级 `AGENTS.md`、现有开发守卫、赛题 AUTHORIZED 范围与生产门禁 **优先于本 Skill**；本 Skill 不授予任何额外权限。本 Skill 管理"目标驱动与连续交付"；`doraemon-local-dev-guard` 管理本地开发环境审计、敏感操作与 Git/测试治理；开发任务需两者时 **叠加加载，禁止覆盖、合并替换或重复复制长规则**。

### 7.2 授权边界（V1.2「执行规则 7 保护现场」）
在明确授权范围内操作。遵守现有项目 `AGENTS.md`、开发守卫、赛题 AUTHORIZED 范围与生产门禁，不修改或绕过它们。版本提交及推送依照项目规则/派工授权执行；禁止上传密钥、真实隐私、Token、Cookie 和 `.env`。

### 7.3 必须停止并请示条件（V1.2「中断与请示门槛」）
**不中断**：普通技术选型、可逆代码改动、已有权限内的工具调用、常规测试、可定位 Bug、低风险修复和已授权任务内的阶段转换。
**必须停止并请示**：超出授权范围；会影响生产安全或真实数据；不可逆删除/覆盖/迁移；高风险权限变更；隐私或凭据外传；新增费用/超预算；业务目标出现无法自行保守解决的实质冲突；关键依赖缺失且无安全替代方案。已有安全门禁的拒绝结果不是可被绕过的"普通技术问题"。
无法继续时，只问 **一个** 真正需要用户决定的问题，同时提供推荐选项、原因和已完成的可保留成果；不得让用户担任技术故障排查员。

### 7.4 任务范围约束（V1.2「使命与适用范围」+ 执行规则 1）
适用于 **BUILD**（开发）、**RESEARCH**（调研）、**AUDIT**（审查）、**ARTIFACT**（交付文档/演示）四类任务；V2 三分法映射：BUILD→CODE_DEV，RESEARCH/AUDIT→RESEARCH（AUDIT 为其模式），ARTIFACT 保留。**仅执行派工时指定的类型和范围，不擅自扩大任务、开启后续阶段或安排其他 Agent**。缺少非关键实现细节时做可逆、保守的技术选择，不把选型题转交用户。

### 7.5 用户视角汇报规则（V1.2「执行规则 8 结果汇报」）
优先报告用户关心的「完成了哪些功能、可在哪里运行、真实验收是否通过、仍有什么差距」。Git/日志作为可追溯证据附在简短技术附录，而不是让用户逐条裁决。交付结论必须为 `PASS / PARTIAL / BLOCKED`，不得因流程执行过就声称完成。

## 8. 会话级上下文复用（V2.0.2 新增）
目标：不重复消费已加载上下文，省 token 且保持规则一致。

1. **CORE 一次**：同一会话内 V2 CORE（SKILL.md）只加载/注入一次；后续任务直接复用，不重新注入全文。
2. **同任务不重读**：同一任务内已读取过的 reference 不得再次全文读取；需要回看时按章节定位读取（锚点），或改读更小的节。
3. **新任务只加增量**：新任务启动时只加载该任务判型所需的新增 reference（按 machine-fields.md 判型规则）；已在本会话加载且仍适用的不重复加载；次类需求写 GAPS，不加载其 reference。
4. **新会话恢复优先台账**：L 级任务开新会话时，恢复入口是 `task-ledger.json`（§6 恢复流程）：先读台账的 next_action/计数/预算/已完成项，再决定加载哪些 reference；**不得重放全部会话历史**，历史只在台账证据不足时按最小范围补读。
5. **注入宿主差异**：dispatch-injected / preview-injected 宿主没有持久会话复用能力时，由派工方负责去重（不重复内嵌同一段规则）；宿主有会话上下文的按本节约束执行。
